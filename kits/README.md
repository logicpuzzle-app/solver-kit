# kits — 手筋ソルバーと難易度判定

パズル種ごとに 1 ディレクトリ。**4 つとも同じ骨格**で書いてある。
新しいパズル種を足すときはこの形に従う。

| | 言語 | 較正 | 状態 |
|---|---|---:|---|
| [`yajilin-kit`](yajilin-kit/) | Rust / TypeScript / Python | puzsq 8,822 問 | 難易度 v5。3ポートがバイト単位で一致 |
| [`slitherlink-kit`](slitherlink-kit/) | Rust | puzsq 1,585 問 | 難易度 v1 |
| [`nurikabe-kit`](nurikabe-kit/) | Rust | puzsq 1,234 問 | 難易度 v1。完解 86% |
| [`akari-kit`](akari-kit/) | Rust | — | 着手中。最初から段階モデル |

## 骨格

```
board.rs           盤面と ID 採番。パズル固有の幾何(光線・部屋分割など)もここ
answer_model.rs    解答の状態。set() が矛盾を Err で返す
answer_methods.rs  手筋が触る唯一の窓口。確定を Recorder に自動で記録する
solution.rs        完成解のルール検証。ソルバーとは独立に実装する
search.rs          制約エンジン。一意性の証明に使う
puzzlink.rs        puzz.link URL の入出力
reasons.rs         手筋の名前と重み
techniques/        手筋。1 つが fn(&mut AnswerMethods) -> Status
solver.rs          段階のカスケードと仮置き
difficulty.rs      難易度スコア
```

### 手筋の書き方

インターフェースは `fn(&mut AnswerMethods) -> Status`(`Advanced` / `Stopped` / `Broken`)。

**`AnswerMethods::set()` が確定を自動で記録する**ので、手筋の側で記録を忘れられない。
記録は 2 つに使う — 解法の説明(どの順でどう決まったか)と、難易度(どの手筋が何回発火したか)。

**盤面を書き換えながら判定しないこと。** 連結成分などを先に計算しておくと、
途中の書き込みでその情報が古くなる。判定を全部済ませてから、まとめて書き込む。
(`white_link` でこれをやってバグらせた。`trace` サブコマンドで見つかる。)

## 難易度の考え方

**主軸は「その問題を解くのに要った読みの段階」。**

```
DP = (段階 − 1) × LEVEL_SCALE + 段階内のスコア
```

手筋を安い順に並べ、止まったら 1 段ずつ上げる。到達した最大の段階が
「その問題を解くのに最低限必要な手筋の集合」になる。段階内のスコア(手筋の発火数と
仮置きの費用)は、同じ段階の中で順序をつけるためだけに使う。

段階の切り方はパズル種ごとに違うが、だいたいこの形になる:

1. 数字・ヒントのまわりの定石(目で見てすぐ分かるもの)
2. 数え上げ(どこに何マス入るか)
3. 連結性(切ったらどうなるかを 1 マスずつ確かめる)
4. 列挙(形を全部並べて共通部分を取る)
5. 仮置き
6. 入れ子の仮置き
7. それでも解けない

### 効くと分かっている項

| 項 | 中身 |
|---|---|
| 段階 | 上記。主軸 |
| 手筋だけで残ったマス数 | 仮置きに入る前、手筋だけで進めなくなった時点の未確定マス数 |
| 浅い仮置きで残ったマス数 | その 1 段上 |
| 解けなかったときの残りマス数 | 段階 7 の中の順序 |

**手筋ごとの重みは較正しても改善しない。**発火数は難易度ではなく盤面の広さで決まる
(10×10 の完解問題で申告★1/★2/★3 の発火数中央値がどれも ±10% 以内)。
15 個の重みを座標降下で当てはめると訓練一致率は上がるが 5-fold CV は下がる。
→ [REJECTED_JA.md](../REJECTED_JA.md)

### 落とし穴

- **解き終わった盤面はどの手筋も `Stopped` を返す。**段階を上げる前に完成判定を入れないと、
  易しい問題まで最上段まで登る(1,228 問中 808 問の段階を間違えた)
- **`LEVEL_SCALE` は段階内スコアの最大値より大きく取る。**入れ子仮置きを既定にしたとき、
  完解問題の 12% が天井に張り付いて順序が潰れた

## 仮置きの入れ子(ぬりかべで確立、2026-08-05)

手筋が尽きたあと、**仮置きの中でさらに仮置きする**。ぬりかべでは完解率が
86.1% → 93.0% に上がった(申告★4 は 56% → 77%、★5 は 15% → 36%、矛盾は 0 のまま)。

段階も 1 つ増える。「深さ 2 が要る」と「それでも解けない」が別物になり、上位が細かくなる。
**手詰まりが多く残っているキットには、まずこれを試す価値がある。**

素朴に実装すると遅すぎて使えない。ぬりかべで効いた対処が 2 つある。

### 否定しやすいマスから試す

仮置きは矛盾を見つけた時点で打ち切るので、**早く当たるほど安い**。
どのマスが矛盾しやすいかは浅い読みで測れる — そのマスを両方の値に置いて手筋だけで
伝播させ、**遠くまで伝播したマスほど制約が強い**(すぐ止まるマスはまわりと繋がっていない)。
この下読みは深さ 0 なので、深い仮置き 1 回より桁違いに安い。

重い 20 問で 965 秒 → 835 秒。**隣接する確定マスの数だけで並べたときは 5% しか縮まなかった**ので、
伝播の距離を使うこと。深さ 1 でも下読みする(深さ 2 の中の入れ子は深さ 1 なので、
そこを速くしないと意味がない)。

### 内側の候補を外側のマスの近くに絞る

外側で 1 マス置いた影響はその近くに出る。遠くを試し直しても、外側の仮定と無関係な計算を
やり直すだけになる。外側で置いたマスの座標を内側へ渡し、そこから一定距離以内の候補だけを試す。

**絞っても嘘はつかない。** 見つかる確定が減るだけで、見つけた矛盾は矛盾のまま。

ぬりかべでの半径ごとの計測(重い 20 問):

| 半径 | 合計時間 | 完解 |
|---|---:|---:|
| 制限なし | 835 秒 | 10 |
| 10 | 768 秒 | 10 |
| 7 | 542 秒 | 9 |
| 5 | 418 秒 | 7 |

10 が「完解を落とさずに縮む」線。全 1,234 問では制限なしより**むしろ良かった**
(完解 1148 対 1146、時間切れ 13 対 18)。打ち切りが減ったぶん解けている。

### 表示側の手当て

深さ 2 だと重い盤面で数十秒〜1 分強かかる。ブラウザで動かすなら**中断できるようにする**こと
(wasm は途中で止められないので、Worker ごと捨てる)。

## 指標は 4 つ見る

| 指標 | 何が分かるか |
|---|---|
| 完解率 | 目標そのもの。ただし階段関数で、手筋 1 つの効果が見えにくい |
| 確定率(確定したマスの割合) | 完解に届かなくても効果が出る |
| **仮置きなしの完解率** | 仮置きは「解けた」を稼ぐが難易度の説明にはならない。手筋が本当に強くなったかはここに出る |
| 段階の分布 | 難易度モデルの主軸 |

## 較正

```sh
python3 measure.py --timeout 60 --jobs 8   # 解決率・確定率・段階の分布
python3 calibrate.py                        # 人手評価との一致率と 5-fold CV
python3 fit_weights.py                      # 係数を 1 つずつ走査
python3 tiers.py                            # 段階の分布と、段階だけでの分類精度
python3 stuck.py --declared 3 --count 5     # 手詰まり盤面を正解と並べる
```

**係数は 1 つずつ走査して、CV が平坦な高原になっているその中を採る。**
最大値をそのまま採るとシードの揺らぎを拾う。多パラメータの自由な降下は
fold ごとに係数が暴れて CV が下がった。

較正コーパスは `https://puzsq.logicpuzzle.app/api/problem/kind/{id}` から取る。
kind: スリザーリンク=1、ましゅ=2、ヤジリン=3、ぬりかべ=6、へやわけ=7、LITS=10、
シャカシャカ=11、美術館=18、数独=19、ダブルチョコ=66。

## 新しいキットを足すとき

1. `board.rs` + `solution.rs`(完成解のルール検証)
2. `puzzlink.rs` + CLI の `show` / `solve`
3. `search.rs`(一意性)— ここで検証スクリプトが書ける
4. `answer_model` / `answer_methods` / `reasons` / `status`(受け皿。ほぼ写すだけ)
5. `techniques/` を 1 つずつ。安い順に段階へ割り当てる
6. 仮置き → 難易度スコア
7. puzsq のコーパスで較正

**手筋を足したら `trace` で 1 問追う。**誰が何を決めたか、どこで矛盾したかが出る。
