# masyu-kit — ましゅの手筋ソルバーと難易度判定

ぬりかべ・美術館で確立した形の 4 種め(ユーザー指定で凍結解除、2026-08-05 着手)。
ヤジリンと同じループパズルなので、辺 3 値(線/×/未定)の盤面表現と
小ループ禁・連結性まわりはヤジリンの設計を下敷きにしている。

## 構成

| ファイル | 役割 |
|---|---|
| `board.rs` | 盤面。辺の幾何(incident / neighbours / edge_cells)を作り置き |
| `answer_model.rs` | 辺ごとの 線/×/未定。線分は Union-Find、閉路は `loop_closed` |
| `answer_methods.rs` | 手筋が触る唯一の窓口。確定の記録もここで行う |
| `solution.rs` | 完成解のルール検証(ソルバーと独立に実装) |
| `search.rs` | 全探索。一意性の判定用 |
| `puzzlink.rs` | puzz.link URL の読み書き(3 進 3 桁 → base27) |
| `solver.rs` | 段階エスカレーション + 仮置き |
| `difficulty.rs` | `段階 × LEVEL_SCALE + 手間`(較正前) |

### マスの状態を持たない

ヤジリンと違い黒マスの概念がないので、状態は辺だけ。「線が通るマスか」は
接する線の本数から毎回導く(美術館の「照らされているか」と同じ理由 —
派生量を状態に持つと、どの手筋が何を決めたかの記録が壊れる)。

### URL の variety 名

読みは `mashu` / `masyu` / `pearl` の 3 つを受ける(pzprjs は mashu を出力、
cspuz は masyu を出力、pearl は pzprjs の alias)。書き出しは pzprjs に合わせて
`mashu`。puzsq のコーパスは 2,777 件が mashu、1 件だけ masyu。
pflag `f`(全マス通過バリアント)は非対応と明示してエラーにする。

## 手筋

| 段階 | 手筋 | 内容 |
|---|---|---|
| 1 | `degree` | マスの次数。線は 2 本か 0 本。残り 1 本の延長・行き止まりの × |
| 1 | `pearl_basic` | 丸の基本。白は直進できる向きが 1 つなら確定、黒は腕を張れる側が 1 つなら確定。角・盤端・壁際・黒丸隣接はぜんぶこの言い換え |
| 2 | `white_neighbours` | 白丸の前後どちらかで曲がる。隣が白丸なら曲がれない(白 3 連の垂直横断もここから出る) |
| 2 | `small_loop_ban` | 同じ線分の両端をつなぐ辺は、完成しないかぎり × |
| 3 | `connectivity` | 丸と線は 1 つのループに乗る。届かないマスの辺は × |
| 3 | `cut_parity` | 直線カットの横断本数は偶数(Jordan 曲線) |
| 3 | `region_parity` | カット偶奇の領域版。出入り口 1 本の袋小路は封鎖、丸入り・出入り口 2 本なら両方線(ヤジリンの「見えない壁」) |
| 4 | `pearl_cases` | 丸の通り方(白 2 通り・黒 4 通り)を全部並べ、どの通り方でも同じに決まる辺を確定。黒丸と斜め白丸の相互作用もここで拾う |

手筋カタログの出典調査(Web、2026-08-05): 黒丸の角・盤端・隣接、白丸の盤端・
3 連・2 連、斜め相互作用、Jordan 曲線パリティ、市松カウンティングを確認。
市松カウンティング(白黒差分の原理)は実装して計測したうえで**却下**
(本線で発火 0 回・完解率不動。REJECTED_JA.md 参照)。

## 使い方

```
cargo build --release --manifest-path rust/Cargo.toml
rust/target/release/masyu solve "https://puzz.link/p?mashu/10/10/..."
rust/target/release/masyu solve "<問題>" --no-trial     # 仮置きを使わない
rust/target/release/masyu solve "<問題>" --tier 2       # 段階 2 までの手筋だけ
rust/target/release/masyu solve "<問題>" --depth 2      # 仮置きの入れ子を深くする
rust/target/release/masyu answer "<問題>"               # 探索で正解を出す
rust/target/release/masyu trace  "<問題>"               # 手筋を 1 つずつ回して経過を出す
python3 fetch_corpus.py                                 # puzsq から較正コーパスを取る
python3 measure.py --timeout 60 --jobs 8                # 解決率と段階の分布
python3 calibrate.py                                    # 難易度の較正
```

`solve` の出力に `EDGES`(辺の総数)がある点が他キットと違う。ましゅの
確定率の分母はマスではなく辺なので、measure.py はこれを読む。

## 現状(puzsq コーパス 2,716 問)

| 状態 | 問題数 |
|---|---:|
| 完解 | **2,713 (99.9%)** |
| 手詰まり | **0** |
| 時間切れ(単独 150 秒でも) | 3(25×25 が 2 問、15×16 が 1 問) |
| 矛盾 | **0** |

手詰まりと時間切れの記録は [testdata/STUCK_JA.md](testdata/STUCK_JA.md)。

### 効いた順の記録

- v1: 基本 8 手筋 + 仮置き(FAST は段階 2 まで) → 完解 87.7%
- v2: + `region_parity`(2,241 回発火)→ 87.8%。**単体ではほぼ動かない**
- v3: 大域 3 種(連結性・カット偶奇・領域の出入り)を **FAST(仮置きの中)にも入れる**
  → **94.4%**。ましゅの終盤は大域の読みで矛盾が出るので、仮置きの反証力が本体。
  region_parity は「仮置きの中で」効く手筋だった
- v4: URL デコーダを pzprjs と同じ寛容さに(短い本体は空マス埋め、末尾の
  `.0` などは読み飛ばし)。**puzsq の 138 問はこの形式**で、v3 までは
  読めずに較正から漏れていた → 完解 99.4%
- v5(モデル v2): 仮置きの入れ子を深さ 2 に(既定 1 → 2)。手詰まり 11 問が
  0 問に(丸ゼロ盤面の候補選び修正 1 問 + 深さ 2 で 10 問)。
  1 辺も確定できなかった対称形も全部割れる

## 難易度較正(2026-08-05、モデル v2、puzsq 2,704 問)

| 指標 | 値 |
|---|---:|
| Spearman(人手評価, DP) | **0.607** |
| 完全一致 | **57.4%** |
| ±1 以内 | 97.2% |
| 5-fold CV 一致率 | 56.2% |

バンド閾値 [1,000,075 / 4,001,457 / 5,006,869 / 5,047,136]。
★換算アンカーは difficulty.rs の `PUZSQ_RATING_POINTS`。★4.5 だけは
バンド閾値でなく「解けない」段階の開始点 6,000,000 に構造固定する
(自由な当てはめは ★4|5 境界を 5,047,136 に置き、★5 の 14 問中 13 問を
★4 側に飲み込む。美術館で確立した理屈)。

fit_weights.py で係数 5 つを 1 つずつ走査した結果、**どの係数も CV が
±0.5pt の平坦な高原**で、初期値から動かす根拠がなかった。ましゅの難易度は
ほぼ段階(どこまで読みが要ったか)だけで決まり、手間の項は同段階内の
順序づけにしか効いていない。

## 移植元について

- 手筋の移植元: `PuzzleTools/sdvx` の MasyuSolver.java(珠の基本・次数・連結・偶奇)
- URL 仕様の正典: `PuzzleTools/pzprjs` variety-common/Encode.js の decodeCircle
- 一意性の突き合わせ: `packages/solver-kit` の masyu.ts(制約エンジン側)
