# Slitherlink Kit — スリザーリンクのソルバーとジェネレータ

スリザーリンクのソルバーと自動生成器（Rust、標準ライブラリのみ）。同じシードを与えれば常に同じ問題が
出ます。設計の詳細と根拠は [DESIGN_JA.md](DESIGN_JA.md) にあります。

## 何をもとにしているか

**手筋ソルバー**は `PuzzleTools/sdvx` の `SlitherSolver.java`（myamya 氏）の手筋を土台に、
`numberSolve` / `nextSolve` / `oddSolve` / `connectWhiteSolve` / `finalSolve` を個別の推論へ分割して
移植したものです。sdvx の手筋は「確定した盤面の検査」寄りで人が使う定石を持たないため、そこへ
標準定石（0 の周り、3–3、斜めの 3–3、角の 1/3 など）と内外手筋を足しています。移植元のメソッド名は
各ファイルの先頭コメントに残してあります。

**制約エンジンと生成器**は本プロジェクトで新規に設計したものです。生成の枠組み（決定的な乱数、
共通 CLI、`verify.sh`）は [NPGenerator 2007 の4言語版](../Puzzle/npgenerator) と
[yajilin-kit](../yajilin-kit/README_JA.md) に倣っています。

## ソルバーが2つある理由

| | 手筋ソルバー | 制約エンジン |
|---|---|---|
| 実装 | `solver.rs`, `techniques/` | `engine.rs`, `search.rs` |
| モデル | 人間の解き方 | ルールが許すもの |
| 用途 | 難易度評価・生成時の判定 | 一意性の証明 |
| 完全性 | なし（手が尽きれば止まる） | あり（決定手続き） |

難易度は人間の推論についての性質なので手筋ソルバーで測ります。「この問題の解は一つだけ」のように
**真であることが要求される**判定は制約エンジンが担います。

## ビルドと実行

```
cd rust
cargo build --release
./target/release/slither <command>
```

## CLI

```
slither solve <problem> [--breakdown]   # 解答・難易度・盤面レンダリング
slither count <problem> [--limit N]     # 解の個数を数える（一意性の証明）
slither calibrate <corpus.tsv> [options] # 人手評価で難易度重みを較正
slither generate-loop [options]         # ループ先行方式で生成
slither generate-pattern [options]      # ヒント配置パターンから生成
slither bench [--count N] [--seed N]    # 生成・求解・計数の時間計測

<problem> はファイルパス、puzz.link URL、または "slither/W/H/body" 形式のコード。

  --seed N            乱数シード（既定 0）
  --size WxH          盤面サイズ（既定 10x10）
  --attempts N        リトライ上限、0 で無制限（既定 100）
  --dp-min N/--dp-max N  難易度の範囲。外れた問題は作り直す
  --dpn-min N/--dpn-max N  正規化難易度の範囲。上限直前で削減を止め、外れた問題は作り直す
  --band NAME         intro|easy|medium|hard|expert|fiendish
  --max-nodes N       探索ノード上限、0 で無制限（既定 200000）
  --symmetry S        none|rot2|rot4|mirror-h|mirror-v
                      （generate-loop は既定 none、generate-pattern は既定 rot2）
  --pattern FILE      ヒント配置パターンを指定（パターンモード）
  --exact-reduce      ヒント削減の判定に完全探索を使う（後述）
  --no-reduce         ヒント削減を行わない
  --refine N          難易度を上げる山登りを N ラウンド行う（既定 0）
  --no-trial          仮置き（先読み）なしで解く
  --breakdown         solve で手筋別の回数・重み・小計を表示
  --threads N         calibrate の要求スレッド数（既定は利用可能な並列数）
  --rounds N          較正の座標降下ラウンド数（既定 20）
  --trial-limit N     較正で各パスに試す仮置き候補数（既定 28、0 は無制限）
  --format F          url|code|text|grid（既定 grid）
  --out FILE          標準出力ではなくファイルへ書き出す
```

## 生成の仕組み

**ループが先。** セルを「内側」「外側」に塗り分け、内側領域の境界を閉路とします。内側集合を空から
成長させ、次の3条件を保つ限りランダムに隣接セルを足します。

- 内側が連結
- 外側（盤外を含む）が連結 — 崩れると閉路が2本になる
- どの格子点にも「その点を囲む4セルのうち内側が対角の2つだけ」という配置が生じない —
  生じるとその点に線が4本集まり、8の字になる

この3条件を保てば境界はちょうど1つの閉路になります。そのあと**境界長を伸ばす局所変形**を行います。
成長だけで作るとコンパクトな塊になって境界が短くなり、盤面の一部に線が1本も通らない問題になるためです。
目標は総辺数の 40〜55%（実問題の実測値は 39〜50%）。

そのうえで全セルに周囲の線の本数を書き込み、ヒントをシャッフル順に削除していきます。削除しても
一意なら削除を確定し、そうでなければ戻します。`--symmetry` を指定した場合は、回転または鏡映で
対応するヒントを一組として同時に削除します。`rot4` は正方形の盤面でのみ使えます。
`--band` または `--dpn-max` で DPN の上限が
決まっている場合は、削除を確定できるたびに DPN を測ります。上限を超えた削除は取り消し、そこで
削減を止めるため、大きな盤面でもヒントを残した易しい問題を生成できます。

### ヒント削減の2つのモード

| モード | 削除の可否の判定 | 速度 | できる問題 |
|---|---|---|---|
| 既定 | 仮置きなしの手筋ソルバーで完解できるか | 速い | 人が手筋で解けることが保証される |
| `--exact-reduce` | 制約エンジンで一意かどうか | 遅い | 一意でありさえすればよい（難問向け） |

`--band hard` / `expert` / `fiendish` を指定した場合は、自動的に `--exact-reduce`
相当へ切り替わります。`intro` / `easy` / `medium` は既定の手筋削減のままです。
実際に選ばれた方式は `REDUCE technique` / `REDUCE exact` として出力されます。
指定範囲へ届かないまま試行上限に達した場合は、試行中に観測した
`dpn_range=最小..最大` と次に試すオプションを標準エラーへ表示します。

既定モードで一意性が保証される理由は、手筋ソルバーの推論がすべて健全（真の必要条件しか使わない。
仮置きも「一方を仮定すると矛盾するので他方が成り立つ」という健全な推論）だからです。手筋だけで
全辺が確定したなら、その盤面の解は唯一であることが証明されています。

10x10・seed 4 での比較:

| モード | 時間 | ヒント数 | DP |
|---|---:|---:|---:|
| 既定 | 0.75 秒 | 40 | 944 |
| `--exact-reduce` | 23.6 秒 | 39 | 3684 |

ヒント1個の差で難易度が大きく変わります。

## 難易度

スコア（DP）は、適用された手筋ごとの重みの総和に、仮置きへの課金を加えたものです。DPは同程度の
問題でも盤面が大きいほど増えるため、セル数による増加分を較正指数で除いた正規化難易度（DPN）を
バンド指定に使います。

```
DP  = Σ weight(手筋) × 回数 + 47 × 仮置きを要した手数 + 597 × 最深の仮置きの伝播²
DPN = DP / (横セル数 × 縦セル数)^0.1929
```

| バンド | DPN | 人手評価との対応 |
|---|---|---|
| intro | < 132 | ★1 の中でも特に易しい側 |
| easy | 132〜396 未満 | ★1 |
| medium | 396〜1145 未満 | ★2 |
| hard | 1145〜2412 未満 | ★3 |
| expert | 2412〜7948 未満 | ★4 |
| fiendish | 7948 以上 | ★5 |

### 生成方式ごとの実測範囲

`--band` を指定すると、その帯に収まるまで生成をやり直します。上限のあるバンドでは、
**上限を超える直前でヒント削減を止める**ので、ヒントを多く残した易しい問題が作れます。
hard 以上では自動的に完全探索削減へ切り替わります。

releaseビルド、既定オプションに `--size` と `--band` だけを加え、seed 1〜3を逐次実行した値です。
DPN は成功3問の最小・中央値・最大、時間は1問あたりの実時間の範囲です。intro / easy / medium は
手筋削減、hard は自動選択される完全探索削減です。

|---|---:|---|---:|---:|---:|
| 手筋 | 8x8 | intro | 3/3 | 93.25 / 105.34 / 112.50 | 0.049〜0.069秒 |
| 手筋 | 8x8 | easy | 3/3 | 292.19 / 312.53 / 332.08 | 0.023〜0.168秒 |
| 手筋 | 8x8 | medium | 3/3 | 542.60 / 547.92 / 595.61 | 0.161〜0.318秒 |
| 完全探索 | 8x8 | hard | 3/3 | 1920.98 / 2346.39 / 2381.82 | 1.467〜2.515秒 |
| 手筋 | 10x10 | intro | 0/3 | 到達範囲は下表 | 0.698〜0.796秒 |
| 手筋 | 10x10 | easy | 3/3 | 308.08 / 364.60 / 376.91 | 0.055〜0.153秒 |
| 手筋 | 10x10 | medium | 3/3 | 472.41 / 756.49 / 793.61 | 0.478〜0.742秒 |
| 完全探索 | 10x10 | hard | 3/3 | 2087.97 / 2173.96 / 2314.74 | 1.873〜6.317秒 |
| 手筋 | 14x14 | intro | 0/3 | 到達範囲は下表 | 1.832〜2.098秒 |

intro に届かなかった各seedの `dpn_range` は次のとおりです。

| サイズ | seed 1 | seed 2 | seed 3 |
|---|---:|---:|---:|
| 10x10 | 137.6..734.6 | 152.7..613.1 | 181.0..686.3 |
| 14x14 | 223.8..974.1 | 256.9..958.7 | 282.2..953.4 |

**intro は小さい盤面でしか作れません。** intro は ★1 の中でも特に易しい側を切り出した帯（DPN 132
未満）で、人手評価には対応する階級がありません。大きい盤面はヒントをすべて残しても手筋の発火回数が
その水準を超えるため、原理的に届きません。実用上は easy が最も易しいバンドです。

届かなかった場合は、到達できた DPN の範囲をエラーメッセージに出します。

```
RESULT GENERATE_FAILED attempts=100 band=intro reason=指定範囲に届かなかった
  dpn_range=152.7..613.1 hint=--exact-reduce を試すか、--attempts を増やしてください
```

重みと閾値は、パズルスクエアの人手評価つき 1,585 問で較正した値です
（DPの5-fold交差検証での Spearman 順位相関 **0.719**、訓練との差 0.004）。人手評価つき 1,585 問での較正の記録と、そこから提案された閾値は
[testdata/CALIBRATION_JA.md](testdata/CALIBRATION_JA.md) にあります。要点は3つです。

`--trial-limit 100 --folds 5 --min-weight 1` で再測定すると、全問（STOPPEDを含む）の較正後相関は
DPが0.721766、DPNが0.726789、5-fold平均はDPが0.716635、DPNが0.722810でした。サイズを固定した
層内相関の加重平均はどちらも0.642538です。同じサイズの中ではセル数による除算が順位を変えないため
当然一致します。全体相関ではDPNがDPをわずかに上回り、サイズ交絡を緩和しています。セル数で完全に
割ると過補正になるため、相関を最大化する指数0.1929を採用しています。

- **矛盾判定は 0 件。** 1,585 問はいずれも人が実際に解いた問題なので必ず解を持ちます。手筋に誤りが
  あれば正しい解を削って矛盾に至るはずで、それが1件も出なかったことは手筋の健全性を実データで
  裏付けています
- **手詰まりの問題を評価から外してはいけません。** 手筋ソルバーの完解率は ★1 で 99%、★5 では 23% と、
  難しい問題ほど解けません。完解した問題だけで相関を測ると、難易度の高い側がほとんど残らないうえ、
  「手筋では歯が立たなかった」という最も強い信号を捨てることになります。手詰まりを
  「途中までの DP ＋ 未確定辺の本数 × 係数」として含めると、Spearman 順位相関は 0.656 → 0.735 に
  上がりました
- **較正が重みを与えたのは先読みの深さで、定石の発火回数ではありません。** 多くの定石は重み 0 に
  なりましたが、これは「その手筋が不要」という意味ではありません。どれも推論としては正しく、
  なければ解けません。発火回数が人手評価を説明しない、というだけです

### 人手評価コーパスによる較正

```
slither calibrate testdata/puzsq-corpus.tsv --rounds 20 --out weights.txt
```

コーパスを標準ライブラリのスレッドだけで並列に解き、完解問題だけの相関と、STOPPED を含む相関を
それぞれ較正前後について表示する。STOPPED の DP は途中までの DP に固定罰点と未確定辺数の重みを
加えた値とし、この2係数を含む全重みを、全非BROKEN問題の Spearman 順位相関を目的に非負整数の
座標降下で調整する。difficulty 1〜5 の完解率と四分位数、隣接クラスの誤分類率を等重みで最小化する
境界、現在の6バンドへの対応も表示する。`--out` は `reasons.rs` の `match` に貼れる腕と追加係数の
提案だけを書き出し、ソース自体は変更しない。

仮置きは大盤面で全未確定辺を試すと一問だけで数分かかるため、較正時だけ各パスの辺 ID 順先頭28本を
既定上限とする。時間ではなく候補数で切るため結果は決定的で、必要なら `--trial-limit 0` で無制限に
できる。要求スレッド数の既定値には `available_parallelism()` を使い、仮置きモデルの同時複製で
メモリを使い切らないよう実働ワーカーは最大2、大型盤面は同時1問までとする。

## 手筋の一覧

sdvx 由来（細分化して移植）: `cell_exact` / `cell_forced` / `vertex_close` / `vertex_extend` /
`vertex_dead` / `parity_line` / `connect_line` / `no_small_loop`

標準定石（新規）: `zero_cell` / `three_pair` / `three_diagonal` / `three_zero_diagonal` /
`three_zero_adjacent` / `corner_clue` / `three_incoming` / `one_blocked_corner` /
`two_blocked_corner` / `clue_corner_pair`

内外手筋: `inside_outside` — セルの内外をパリティ付き union-find で管理し、判明済みの関係から辺を
確定します。真に新しいのは格子点まわりの推論で、格子点を囲む4セル A,B,C,D について
「A=D かつ B=C かつ A≠B」だけが禁止されている（その場合だけ次数が4になる）ことから、
3つの関係のうち2つが判明すれば残り1つが決まります。

## 検証

- **pzprjs の公式テストとの一致。** `pzprjs/test/script/slither.js` にある 5x5 の問題について、
  デコード結果と正解（横線12本・縦線18本）が本実装の出力と完全に一致します
- **実問題での回帰。** [testdata/unique-problems.txt](testdata/unique-problems.txt) の5問（5x5〜12x10）
  について、一意性の証明と手筋ソルバーの解の一致を検査しています。同ファイルには、PuzzleTools 内で
  見つかったが**問題として成立していなかったデータ**（解なし・複数解・本体がセル数を溢れるもの）も、
  除外の理由つきで記録してあります
- **手筋の健全性。** 生成した問題50問について、手筋ソルバーが確定した辺がすべて制約エンジンの
  唯一解と一致することを検査しています。加えて、無作為な小盤面の全解を列挙し、各手筋が確定する辺が
  全解で成り立つことを手筋ごとに検査しています
- **生成物の正しさ。** 生成した閉路が単一閉路であることを、生成アルゴリズムとは独立した
  ルール検証器（`solution.rs`）で毎回確認しています
- **決定性。** 同一シードから同一の問題が出ることを `rust/verify.sh` で確認します
