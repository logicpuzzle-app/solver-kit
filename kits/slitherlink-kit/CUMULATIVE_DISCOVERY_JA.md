# 局所手筋の累積探索結果

## 実行条件

`discover` を幅・高さ別に一般化し、次の順で新規パターンを受け渡した。

```sh
cd rust
cargo build --release --bin discover

./target/release/discover --size 2x2 --threads 8 \
  --emit-novel discovery_output/novel_2x2.bin \
  --out discovery_output/novel_2x2.tsv

./target/release/discover --size 2x3 --threads 8 \
  --known discovery_output/novel_2x2.bin \
  --emit-novel discovery_output/novel_2x3.bin \
  --out discovery_output/novel_2x3.tsv

./target/release/discover --size 3x3 --threads 8 \
  --known discovery_output/novel_2x2.bin,discovery_output/novel_2x3.bin \
  --emit-novel discovery_output/novel_3x3.bin \
  --out discovery_output/novel_3x3.tsv

./target/release/discover --size 3x4 --threads 8 --max-clues 5 \
  --known discovery_output/novel_2x2.bin,discovery_output/novel_2x3.bin,discovery_output/novel_3x3.bin \
  --emit-novel discovery_output/novel_3x4_max5.bin \
  --out discovery_output/novel_3x4_max5.tsv
```

既存19手筋は各段階で常に既知とした。読み込んだ局所パターンは、調査領域に完全に収まる全方向の
部分窓へ適用し、既存19手筋と交互に変化が止まるまで伝播した。既存の埋め込み3x3表は使用していない。

長方形の代表元は恒等・180度回転・水平鏡映・垂直鏡映の4対称だけで畳んだ。既知パターンとして
適用するときは90度回転した別寸法の窓にも展開した。したがって3x4内では2x3窓4個と3x2窓3個の
合計7個を適用している。依頼文の「2x3窓が6個」は軸に平行な部分長方形の数とは一致しないため、
「収まるすべての部分窓」を優先して重複のない7個とした。3x3窓は2個、2x2窓は6個である。

## 集計

| 段階 | 対象配置 | 代表元総数 | 軌道和 | 確定あり代表 | 新規代表 | 新規実配置 | 平均新規辺 | 探索時間 | 健全性 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 2x2 | 625 | 120 | 625 | 66 | 7 | 30 | 2.714 | 3 ms | 7/7 |
| 2x3 | 15,625 | 4,125 | 15,625 | 2,264 | 199 | 763 | 2.910 | 308 ms | 100/100 |
| 3x3 | 1,953,125 | 252,375 | 1,953,125 | 95,861 | 8,717 | 66,848 | 3.137 | 16,792 ms | 100/100 |
| 3x4・5ヒント以下 | 952,913 | 240,401 | 952,913 | 168,029 | 1,692 | 6,729 | 2.360 | 24,774 ms | 100/100 |

各段階でBurnsideの補題から代表元総数を独立に計算し、完全列挙した代表元の軌道サイズ合計が
対象配置数と一致することを確認した。3x4全体についても、4対称で代表元61,140,625、
配置244,140,625と算出できている。

処理全体（代表列挙・探索・健全性検査・出力）の実測は、2x2が6 ms、2x3が343 ms、
3x3が18,000 ms、3x4の5ヒント以下が26,315 msだった。

### 3x4の探索範囲を決めるためのベンチマーク

最初に指示どおり、コード順の代表元100,000個だけを処理した。

- 処理時間: 13,879 ms
- 1代表あたり: 0.138790 ms
- 全61,140,625代表の推定: 8,485,707 ms = **2.357時間**
- ベンチマーク範囲の軌道和: 397,478

推定が1時間を超えたので全探索は行わなかった。実問題のヒント密度約40%に対応し、サンプル誤差を
持たない「12セル中5ヒント以下」を選んだ。この部分集合は952,913配置、240,401代表であり、
その全件を調べた。コード順100,000代表は数値の小さい疎配置へ偏り新規0件だったため、
新規件数の推定には用いていない。

## 代表例

以下の盤面では `━` と `┃` が新規Line、`×` が新規Crossであり、既知側ですでに取れる辺は描いていない。
全例について、新規辺を一つずつ反対状態に固定すると局所制約探索の全枝が矛盾することを確認した。
さらに健全性検査では、局所領域を実盤面中央へ置き、反対状態を持つ大域解が存在しないことを
制約エンジンで全探索した。

### 2x2

1. `33/..` — 新規1辺

   隣接3–3で既知手筋が外側のLineを決めた後、中央頂点へ3本目が入るのを防ぐ延長Crossである。

   ```text
   ● ● ●
    3 3
   ● ● ●
     ×
   ● ● ●
   ```

2. `31/1.` — 新規4辺

   3の三辺要求と二つの1の上限が同じ内部頂点を共有する。四つの新規Crossは各々、逆をLineにすると
   いずれかの1が2本になるか、内部頂点が次数1/3になる。短い一方向の定石名は付けられない。

   ```text
   ● ●×●
    3 1×
   ● ● ●
   ×1
   ●×● ●
   ```

3. `33/1.` — 新規1辺

   3–3が要求するLine配置を下側の1が制限し、1の右辺をLineにする分枝がすべて矛盾するためCross。

   ```text
   ● ● ●
    3 3
   ● ● ●
    1×
   ● ● ●
   ```

4. `31/11` — 新規4辺

   上の3と三つの1の連鎖である。どの新規Crossも逆にすると、隣接する1の上限と3の下限を同時に
   満たせない。これ以上簡潔な人手説明は不明。

   ```text
   ● ●×●
    3 1×
   ● ● ●
   ×1 1
   ●×● ●
   ```

5. `13/21` — 新規4辺

   1–3と2–1が内部頂点を介して相互作用する。局所二分岐の双方で表示した4辺が同じCrossになるが、
   短い定石としての説明は不明。

   ```text
   ●×● ●
   ×1 3
   ● ● ●
    2 1×
   ● ●×●
   ```

### 2x3

1. `.3/.2/0.` — 新規4辺

   0が下端の候補を消し、中央2の残り本数と内部頂点の次数0/2が上の3まで伝播する
   0–2–3連鎖である。4辺を一つの短い定石として説明する方法は不明。

   ```text
   ●×●━●
     ┃3
   ●×● ●
      2
   ● ● ●
    0
   ● ● ●
   ```

2. `.3/2./0.` — 新規3辺

   縦に接する0と2が2の出口を制限し、その二通りの出口を上の3が一方へ絞る。表示3辺は両分枝の
   共通部分である。

   ```text
   ● ●━●
      3┃
   ● ● ●
   ┃2
   ● ● ●
    0
   ● ● ●
   ```

3. `3./2./0.` — 新規2辺

   同じ列の3–2–0連鎖。0からのCrossを起点に2の必要Line数を数え、3の三辺要求まで伝播すると
   上端Lineと中央右Crossが残る。

   ```text
   ●━● ●
    3
   ● ●×●
    2
   ● ● ●
    0
   ● ● ●
   ```

4. `1./.2/0.` — 新規2辺

   0と中央2の相互作用が上の1の二候補を同時に制限する。表示Crossを逆にした場合の矛盾は確認できるが、
   一方向の簡潔な人手説明は不明。

   ```text
   ●×● ●
   ×1
   ● ● ●
      2
   ● ● ●
    0
   ● ● ●
   ```

5. `3./.2/0.` — 新規2辺

   0で閉じた下端から斜めの2を経て3へ伝わる。表示Lineは全局所解の共通部分だが、
   短い定石としての説明は不明。

   ```text
   ●━● ●
   ┃3
   ● ● ●
      2
   ● ● ●
    0
   ● ● ●
   ```

### 3x3

1. `..3/.2./0..` — 新規6辺

   既存調査にも現れた0–2–3の斜め連鎖。0の四辺Cross、中央2の二本要求、右上3の三本要求を
   内部頂点の次数0/2と交互に伝播すると表示6辺が残る。

   ```text
   ● ● ● ●
       ┃3
   ● ●×●━●
     ┃2×
   ● ●━● ●
    0
   ● ● ● ●
   ```

2. `..3/.2./3..` — 新規4辺

   対角に向かい合う二つの3を中央2が結ぶ。中央2の取り方を二分しても、両端の3の外側二辺ずつは
   共通してLineになる。

   ```text
   ● ● ●━●
        3┃
   ● ● ● ●
      2
   ● ● ● ●
   ┃3
   ●━● ● ●
   ```

3. `..1/.1./0..` — 新規2辺

   0が左下を閉じ、中央1の唯一性が右上1へ伝播する。右上1の上・右をLineにする分枝が消えるため
   二辺ともCross。

   ```text
   ● ● ●×●
        1×
   ● ● ● ●
      1
   ● ● ● ●
    0
   ● ● ● ●
   ```

4. `..3/.1./0..` — 新規2辺

   0–1で中央付近のLine候補が制限され、右上3は残る三辺を使う必要がある。表示二辺がLineになる
   ことは分枝検査で確認できるが、既知定石だけの短い説明は不明。

   ```text
   ● ● ●━●
        3┃
   ● ● ● ●
      1
   ● ● ● ●
    0
   ● ● ● ●
   ```

5. `..1/.2./0..` — 新規2辺

   0から中央2へ伝わる制約が右上1の使用可能辺を二本消す。人手向けの簡潔な連鎖表現は不明。

   ```text
   ● ● ● ●
       ×1
   ● ● ●×●
      2
   ● ● ● ●
    0
   ● ● ● ●
   ```

### 3x4（5ヒント以下）

1. `0../.2./.2./0..` — 新規9辺

   左上下の二つの0を境界条件として、縦に並ぶ二つの2の出口を数える。中央の各頂点は次数0/2なので、
   二つの2の間と左右へLine/Crossが9辺連鎖する。

   ```text
   ● ● ● ●
    0
   ● ●━● ●
     ┃2×
   ●×●×●×●
     ┃2×
   ● ●━● ●
    0
   ● ● ● ●
   ```

2. `..0/.2./2../0..` — 新規8辺

   対角位置の0が二つの2の候補を反対側から削る。二つの2の取り方を分岐しても表示8辺は共通する。
   一本ずつ追うより集合として得られる型で、短い説明は不明。

   ```text
   ● ● ● ●
        0
   ● ●━● ●
     ×2┃
   ●━●×● ●
   ×2┃
   ● ●━● ●
    0
   ● ● ● ●
   ```

3. `.0./2../2../.0.` — 新規8辺

   上下の0と縦に並ぶ二つの2による対称形。0側を使えないため2のLineが外側へ回り、
   中央頂点の次数制約が残りをCrossにする。

   ```text
   ● ● ● ●
      0
   ●━● ● ●
   ×2┃
   ●×●×● ●
   ×2┃
   ●━● ● ●
      0
   ● ● ● ●
   ```

4. `.30/.../.2./0..` — 新規6辺

   上の0が隣接3の使える三辺を固定し、下の0が中央2の候補を固定する。離れた二組が内部頂点の
   次数制約を介して接続する。表示6辺全体の簡潔な人手説明は不明。

   ```text
   ● ● ● ●
      3 0
   ● ● ● ●

   ●━●×●━●
     ┃2×
   ● ●━● ●
    0
   ● ● ● ●
   ```

5. `.03/.../.2./0..` — 新規5辺

   前例の0–3の順を反転した非対称形。上の3と下の2が別々の0で候補を削られ、中央の次数制約を
   介して5辺が共通確定する。短い定石名は不明。

   ```text
   ● ● ● ●
      0 3
   ● ● ● ●

   ● ●×●━●
     ┃2×
   ● ●━● ●
    0
   ● ● ● ●
   ```

## 傾向

新規代表の割合は、2x2の5.83%、2x3の4.82%、3x3の3.45%、3x4・5ヒント以下の0.70%と
段階的に下がった。領域が広がるほど新規代表の絶対数は一度増えるが、前段の全方向部分窓を累積すると
候補全体に占める固有パターンの比率は明確に減る。

3x4は5ヒント以下だけなので絶対数を3x3全体と直接比較できない。一方、実問題に近い密度の
完全部分集合でなお1,692代表が残ったため、3x4固有の相互作用は少数ながら消えてはいない。

## 回帰・健全性

- 累積なし2x2は従来どおり新規7代表・30配置。
- 累積なし3x3は従来どおり新規22,224代表・171,593配置。
- 累積なし3x3の成立105,957、矛盾146,418、確定あり95,861、
  `SOLVER_BROKEN` 554代表・4,017配置も従来値と一致。
- 新規パターンの中央埋め込み健全性検査は、2x2では全7件、それ以外は各100件成功。
- `cargo test`: 64件成功、失敗0。
- `cargo build --release`: 警告0。

## 出力形式

`.bin` は新規パターンだけを保持する固定長形式である。

- 8 byte: magic `SLPNOV01`
- 1 byte: 幅
- 1 byte: 高さ
- 1 byte: 辺数
- 1 byte: 予約
- 8 byte: レコード数
- 各レコード32 byte:
  - 8 byte: 5進ヒントコード
  - 1 byte: 軌道サイズ + 7 byte予約
  - 8 byte: 新規Lineマスク
  - 8 byte: 新規Crossマスク

ファイル読み込み時に対称形を展開してハッシュ索引へ入れる。探索結果としてメモリに残すのは集計値と
新規パターンだけであり、成立する全配置や全確定パターンは保持しない。
